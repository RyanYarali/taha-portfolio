Cafe Sales Data Profiling

Before anyone can analyze a dataset, someone has to find out what's wrong with it. I profiled a messy cafe sales file to measure how complete and valid it really was, and turned that into a cleaning plan.

Role
Data profiling & analysis
Tools
Python, Pandas, Jupyter
Type
BCIT academic project
Focus
Completeness, validity, duplicates

The problem

The cafe's sales data looked usable at first glance, but placeholder text like ERROR and UNKNOWN was mixed into real fields alongside true blanks.

Any revenue or product analysis built on it would be quietly wrong. The question: how bad is it, where exactly, and what should be fixed first?

What I did

  1. Examined structure & data typesChecked every column's type to catch numbers stored as text and other mismatches.
  2. Measured missing & invalid valuesCounted true nulls and also the ERROR and UNKNOWN placeholders that a plain null count misses.
  3. Checked distinct values, duplicates & IDsReviewed category values, duplicate records and transaction IDs for validity.
  4. Summarized the quality issuesTurned the profile into a per-column summary that guided cleaning and validation.

Key findings

      

        
Hidden gapsPlaceholders hid real gapsERROR and UNKNOWN text sat in real fields, so a plain null count under-reported what was missing.

        
ValidityFilled isn't the same as validA value can be present and still wrong. Validity needs its own checks on types, categories and IDs.

        
UniquenessDuplicates & IDs need a checkChecking duplicate records and transaction IDs comes before any sales total can be trusted.

        
OutcomeA plan, not just a listThe per-column summary showed what to fix first and what to flag, which turned profiling into a cleaning plan.
